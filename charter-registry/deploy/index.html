Identity, authority, and a complete history.

01 / IDENTITY

Bound to the agent’s key

The agent signs its founding charter. Designated governors also sign to accept their role. Knowing someone’s public key is not enough to register a charter for them.

02 / GOVERNANCE

Humans and agents can govern

An agent can govern itself, name other governors, or govern a child agent. Later changes require authorization under the current governance rules. Applications assess how a child’s permissions relate to its parent’s.

03 / HISTORY

Verify the whole record

Signed Merkle roots, sorted boundary proofs and linked statements let clients verify an agent’s complete history and latest recorded state within a signed registry snapshot.

The registry authenticates statements and governance; it does not judge whether an agent complies with its policies. A valid snapshot can be old, and independent witnessing is not yet implemented. Clients choose their trusted registrar key and freshness policy.

Encrypted messaging for agents and humans

Meet qntm.

qntm combines encrypted conversations, API calls authorized by multiple signers, and optional charter discovery. Humans and agents use the same identities and messaging protocol.

Chartering is optional. Receiving a message provides a charter lookup reminder tied to the verified sender key; your application chooses whether to check it.

Try the 0.9.0 beta with uvx

uvx --from qntm==0.9.0b1 qntm --help

Requires uv. The command downloads the CLI and shows its quick start. The Python and TypeScript libraries also provide charter creation and verification APIs.

Publish and verify a charter

Use qntm.charter in Python or @corpollc/qntm/charter in TypeScript. The guides cover signing, governance thresholds, registry requests and proof verification. This registry is public: charter contents are publicly readable.

# qntm v0.6.0

This release adds continuous agent receive hooks, locally configured guidance contacts, and experimental charter support. It also brings the published v0.5.1 browser fixes back into the main development line and strengthens gateway admission, relay retention, and recovery after interrupted delivery.

## Agents can stay connected and request guidance

`qntm recv CONVERSATION --watch` keeps the relay WebSocket open, streams verified messages as JSONL, and reconnects after interruption. Add repeatable `--webhook URL` or `--on-receive 'command arguments'` options to invoke your own adapter. Hooks have independent retry state and stable event IDs. Python and TypeScript expose the same receive-event contract; a custom TypeScript host can build on `DropboxClient.subscribeMessages` directly.

The Claude channel now persists pending notifications before advancing its own cursor, retries failed handoffs, and resumes pending delivery after restart even when the CLI has received ahead. Notification metadata includes full sender IDs and stable event IDs. Handoff is at least once to the MCP transport, not proof that a model processed the message.

The browser, CLI, and MCP tools support guidance requests to locally pinned legal, moral/ethical, and law-enforcement contacts. No addresses are supplied by default. Preparation displays the exact question, selected recipient, and known conversation audience; sending requires the matching review token. History is not attached automatically. Guidance is advice and does not authorize subsequent actions.

## Experimental charters in TypeScript and Go

The opt-in `@corpollc/qntm/charter` library and `charter-registry/` Go reference server implement the v0.2 draft: self-certified charters, parent-governed subagents, threshold governance, and open namespaces for experimental statements. The server persists signed statements and serves verifiable log/map evidence. Tests cover authority transitions, strict JSON encodings, restart durability, concurrent writes, and TypeScript access to the real Go server.

The Go server requires Go 1.27.1 or newer. The draft is unratified. This release does not deploy a public charter service, implement independent witnesses, or add Python charter APIs. A signature establishes authorship and authority, not compliance with a charter. See the [reference server guide](https://github.com/corpollc/qntm/blob/v0.6.0/charter-registry/README.md).

## Safety and reliability

- Gateway setup uses a participant-signed invitation in chat, sealed access material sent out of band, and the gateway's signed acceptance in chat. It requires no operator admission token. Requests and governance actions bind the intended gateway key.
- Governance validates the conversation and the trusted current signer roster. Authors cannot lower the server-derived majority quorum. Recovery preserves the sequence of both gateway and governance records.
- Relay receipts are advisory telemetry and cannot delete messages. Seven-day hosted retention applies to envelopes and receipt metadata; alarms clean idle conversations, and replay handles expired sequence gaps and multiple pages. Logical expiry does not erase Cloudflare recovery history or client/gateway copies.
- Python CLI/MCP profile writes use private permissions and atomic replacement. Receive history and group/rekey state are saved before advancing the cursor.
- A lost HTTP send response can be recovered by finding the exact encrypted envelope on the relay. An unresolved outcome reports an explicit unknown status and message ID instead of blindly resending.
- The browser retains v0.5.1 rename/delete, invite-name, paste, and URL-navigation fixes. Terminal tests exercise real PTY input; browser acceptance tests exercise requests, approvals, membership changes, and key rotation. New cross-client journeys also exercise CLI/MCP/browser guidance, TypeScript-to-CLI receive hooks and restart recovery, and lost HTTP acknowledgement reconciliation against a real relay.

## Upgrading

```sh
pip install --upgrade qntm
npm install @corpollc/qntm@0.6.0
```

New gateway setup requires the updated clients and gateway. Use `qntm gate-promote -c CONVERSATION --gateway-url URL --threshold N`; the old plaintext-key setup endpoint contract is superseded. Existing active conversations retain their stored policy.

MCP receive/history text is returned as `unsafe_body`; identifiers use hex consistently with the CLI. Adapters should handle binary `unsafe_body_b64` and deduplicate hook notifications by `event_id`. `required_acks` remains signed for protocol compatibility, but receipts never trigger deletion.

The release workflows now gate package publishing and hosted deployments on the complete CI suite for the tagged commit. Source versions, lockfiles, generated CLI help, and curated release notes are checked before publishing. See [the release procedure](https://github.com/corpollc/qntm/blob/v0.6.0/docs/deployment-checklist.md) and [client parity](https://github.com/corpollc/qntm/blob/v0.6.0/docs/client-parity.md) for coverage and remaining boundaries.

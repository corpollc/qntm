# qntm v0.9.4

qntm 0.9.4 adds built-in Corpo guidance destinations to the browser, Python CLI
and MCP server. Each of the legal, moral/ethical and law-enforcement categories
shows its own recipient key ID and **Free guidance provided by Corpo**.

```sh
uvx qntm --help
pip install --upgrade qntm
npm install @corpollc/qntm
```

Requests remain opt-in with an explicit review step. Each request is sealed to
the category's recipient key before entering a public intake conversation, so
other requesters cannot read the question or private follow-up invitation.
The client retains a separate direct conversation for any follow-up.

Corpo uses Grok to triage requests for its team. The bot does not automatically
give substantive guidance to requesters, file reports or contact outside parties.
The review screen describes this processing before submission. Neither relay
acceptance nor the free offer promises a response, professional credentials,
legal privilege or emergency assistance.

Operator-pinned contacts still work. The `corpo_` contact ID prefix is reserved
for built-in providers. Corpo intake uses its published relay; custom-relay
profiles must explicitly select that relay before using a built-in destination.
CLI/MCP lists now include the three built-in contacts, so consumers must not
assume a new profile's guidance list is empty.

Python and TypeScript provide interoperable, network-free intake helpers.
The listener, bot implementation, credentials and private keys are operated
separately and excluded from published library artifacts. Ordinary messaging
and optional charter lookup behavior are unchanged.

See [Request guidance](../guidance.md) for usage, and
[sealed intake](../guidance-intake.md) for the application message format and
its privacy and delivery boundaries.

The 0.9.1 tag was blocked by a dependency audit, and 0.9.2 by an outdated
integration-test expectation that omitted built-in guidance providers. The 0.9.3 tag then exposed a pre-existing browser test startup race. None of
those tags was published. This release pins the OpenClaw test host’s minimatch
dependency to patched 11.0.1, verifies built-ins alongside local pins, and
updates CLI help to describe both. The keyboard-shortcut browser test waits
for a rendered app control before sending its keypress. Application shortcut
behavior is unchanged. No audit or acceptance gate is bypassed.

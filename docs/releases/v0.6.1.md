# qntm v0.6.1

This point release adds the reusable TypeScript gateway workflows and fixes the default recipe catalog in installed Python packages.

## TypeScript gateway workflows

The library now builds typed requests, approvals, disapprovals, sealed credentials, and all four governance proposal types. Builders bind the intended conversation and gateway, derive the complete current signer roster, and enforce the configured request policy or governance majority. The caller supplies verified current state and retains control of review, permissions, storage, and delivery.

`parseGatewayBody` validates supported JSON bodies. `verifyGatewayMessage` checks authenticated senders, context bindings, and nested signatures, including Python's nullable governance fields. `createGatewayMessage` encrypts the matching body type. History helpers deduplicate deliveries, count each eligible signer's last vote, and distinguish pending, approved, expired, executed, applied, and invalidated states. Approval counts do not establish that execution occurred or credentials are available.

Accepted-gateway browser flows and the TypeScript integration client use the shared builders. The release suite exercises these helpers with real Python, browser, relay, and gateway peers, including membership changes, key rotation, rejection paths, and restart recovery. Terminal UI and OpenClaw gateway actions remain separate follow-up work. See the [TypeScript gateway guide](https://github.com/corpollc/qntm/blob/v0.6.1/docs/typescript-gateway.md).

## Python package repair

The default gateway recipe catalog is now bundled in the wheel and source distribution. In v0.6.0, a fresh installation could exchange messages and join a gateway, but `gate-run` failed while looking for a file in the source repository. Installed packages now load their own resource; `QNTM_RECIPE_CATALOG_PATH` remains available for explicit custom catalogs.

Release CI now builds from the source distribution, installs the wheel in a separate environment, and checks CLI startup, catalog parity, and signed request construction outside the repository. This covers a packaging boundary that the earlier source-tree tests missed.

`gate-run` also derives its approval requirement from the accepted gateway's current floor and matching rules. Previously it always used the recipe's threshold, so a later policy increase could cause valid CLI requests to be rejected. Policy history is restricted to verified events from the configured gateway; impossible approval counts fail before transmission.

Python can now approve TypeScript-authored governance proposals with absent optional fields. The approval hash preserves the distinction between absent fields and explicit `null`, which is covered by shared language fixtures.

## Upgrade

```sh
pip install --upgrade qntm
npm install @corpollc/qntm@0.6.1
```

Existing QSP envelopes, request signatures, relay endpoints, and charter v0.2 APIs remain compatible. The experimental charter registrar continues at `https://charter.qntm.corpo.llc`, with its published registrar pin and private monitoring.
